Private inventory system for physical storage devices

Catalog HDDs, SSDs, USB media and LTO archives with compact physical tags. Keep encryption passwords, notes, file snapshots and drive metadata in a separately protected local database.

DownloadsExplore the source

An archive you can actually navigate

Physical identification

Five-field compact tags with a per-database schema, typed media and capacity dictionaries, and a per-drive random salt.

Encrypted credential vault

Store volume passwords, encryption methods, private notes and tag mappings in a locally encrypted .dpdb container.

File-level catalog

Build file snapshots, browse directory trees and search offline for files across archived media.

Calculator interface

Optionally show a functioning calculator before opening DiskPass, using a distinct access code and protected settings.

Physical tag formation

Five attributes are encoded using a database-specific block order and keyed check characters.

The tag is a pseudonymous identifier, not ciphertext. Block patterns may remain observable.

Passwords belong behind authenticated encryption

Two independent layers protect modern PQC databases: an OpenPGP-signed ML-KEM/Kyber key envelope and an XChaCha20-Poly1305 authenticated payload. Compatibility and policy checks occur when opening and saving.

Physical tags are identifiers, not ciphertext. A calculator interface or steganographic carrier does not replace encryption.

OpenPGP + ML-KEM

GPGME handles recipient keys, key envelopes and signature verification. PQC encryption requires a compatible GnuPG 2.5+ engine; signatures are not post-quantum.

XChaCha20-Poly1305

The opaque .dpdb payload is authenticated and encrypted, with AAD binding for the envelope header and size-bucket padding.

Encrypted database structure

Conceptual Argon2id/XChaCha20-Poly1305 workflow; other key-protection modes are not shown.

OpenPGP signatures are not post-quantum; recipient key IDs can remain visible.

Steganographic storage

The diagram illustrates embedding and recovering an encrypted database from a carrier file.

Steganography is not encryption. LSB/DCT embedding may be detected, and transcoding can destroy the payload.

01Install build dependencies

sudo apt install git build-essential pkg-config \
  libgtk-3-dev libglib2.0-dev libgpgme-dev \
  libsodium-dev libcjson-dev libjpeg-dev libwebp-dev \
  libpango1.0-dev liblzma-dev imagemagick \
  bluez fonts-dejavu-core

02Clone and build

git clone https://github.com/Sergei768/Diskpass.git
cd Diskpass
chmod +x ./build.sh
./build.sh

03Launch DiskPass

diskpass

Run build.sh as a regular user, not with sudo. The build requires GPGME ≥ 1.24.1; PQC operation also requires GnuPG 2.5+ with ML-KEM support. Older distributions may not provide these versions.
