物理ストレージ機器を非公開で管理するシステム

HDD、SSD、USB、LTO の保管庫を短い物理タグで整理。暗号化パスワード、メモ、ファイルのスナップショット、媒体情報を保護されたローカルデータベースで管理します。

ダウンロードリポジトリを見る

検索できる物理メディア台帳

媒体の識別

5要素タグ、データベース固有の並び順、種類・容量辞書、媒体ごとのランダムソルト。

暗号化された保管庫

パスワード、暗号方式、メモ、タグの対応をローカル .dpdb に保管。

ファイル索引

ファイル構造の記録、フォルダ閲覧、オフライン検索。

電卓モード

別のアクセスコードを持つ電卓型インターフェースを任意で使用。

物理タグの生成

5つの属性をデータベース固有の順序で符号化し、各ブロックに秘密鍵に基づく検査文字を追加します。

タグは仮名識別子であり暗号文ではありません。ブロックの統計的特徴は残る場合があります。

秘密は認証付き暗号で保護

新しい PQC データベースは署名付き ML-KEM/Kyber OpenPGP 鍵エンベロープと XChaCha20-Poly1305 の AEAD ペイロードを使用します。

物理タグは暗号文ではなく識別子です。電卓画面やステガノグラフィは暗号化の代わりにはなりません。

OpenPGP + ML-KEM

GPGME が鍵と署名を処理。PQC には GnuPG 2.5+ が必要で、署名自体は耐量子ではありません。

XChaCha20-Poly1305

.dpdb の AEAD、AAD ヘッダー認証、サイズバケットによるパディング。

暗号化データベースの構造

Argon2id/XChaCha20-Poly1305 の概念図です。他の鍵保護方式はここには含まれません。

OpenPGP署名は耐量子署名ではなく、受信者の鍵IDが見えることがあります。

ステガノグラフィ保存

この図はキャリアファイルへの暗号化データベースの埋め込みと抽出を示します。

ステガノグラフィは暗号化の代替ではありません。LSB/DCT 埋め込みは検出される可能性があり、トランスコードでペイロードが失われることがあります。

ソースからビルドプロジェクトの README と build.sh に基づく手順 · Debian / Ubuntuビルド手順を表示

01依存パッケージをインストール

sudo apt install git build-essential pkg-config \
  libgtk-3-dev libglib2.0-dev libgpgme-dev \
  libsodium-dev libcjson-dev libjpeg-dev libwebp-dev \
  libpango1.0-dev liblzma-dev imagemagick \
  bluez fonts-dejavu-core

02クローンしてビルド

git clone https://github.com/Sergei768/Diskpass.git
cd Diskpass
chmod +x ./build.sh
./build.sh

03DiskPass を起動

diskpass

build.sh は sudo を使わず一般ユーザーで実行してください。GPGME ≥ 1.24.1 が必要です。PQC には ML-KEM 対応の GnuPG 2.5+ も必要です。古いディストリビューションでは必要なバージョンが利用できない場合があります。
